# 先反推画风，再复刻

适用于用户提供画风参考的生图、画风转换及视频复刻中的人物和场景生成。先完成参考图绘画语言分析，再编写实际生成提示词；不跳过分析直接使用“动漫风”“精细插画”等标签。已有用户明确给出的反推时，先结合实图理解并采用其最新版本，不反复要求确认。用户未要求停顿时，反推完成后可直接继续已授权的复刻。

## 反推步骤

1. 实际查看全部必要参考，区分画风参考、内容/构图源图、人物身份和场景布局参考。截图UI、字幕等不是画风组成。
2. 剥离角色设计、题材、姿势、机位、背景物件，分析绘画语言：线条粗细/颜色/闭合程度；固有色与分层上色；阴影硬软边的主次及分布；局部渐变；环境色进入何处；头发高光组织；皮肤和衣物的材质概括；明度、饱和度、笔触及后期光效。
3. 区分画法与光照条件：冷蓝夜景不能自动变成所有白天镜头的固定蓝色滤镜；俯视与仰视是构图差异，不证明画风不同。观察实际局部，不能以气氛“柔和”推断所有阴影均为软边，也不能以“赛璐璐”推断完全没有渐变。
4. 给出清楚的主次判断和纯画风正向/负向词。描述边缘、分层和混色如何实现，不仅列抽象风格词。不为身份一致而锁死源图的线条、阴影与材质，否则无法真正转换。用户最新反推优先，旧版本注明被替代，不能混进当前prompt。
5. 将反推保存到当前项目中间文件的提示词维护位置，实际提交prompt使用该版本。分别说明参考图职责；工具须实际接收必要参考。身份源图只决定需要保留的身份等内容，画风图决定绘制方式，不移植画风图人物、服装、家具与构图。

## 复刻与验收

- **改提示词即衔接生图验证**：在已授权生图任务中，用户提出修改画风/内容提示词后，完成反推与修改、保存新版本，即直接生成该轮图片、实看审核并展示，不等待用户再次说“生成”。不得只交提示词并称“尚待验证”就停止。已有当前未调用修改稿直接继续执行。用户明确仅要文本/先审提示词/暂停生图，以及没有在制生图任务的纯skill维护请求除外。
- 次数与采用边界继续有效：已达到补救上限后，用户新的修改指令可授权本轮一次改词重绘；完成后交用户审核，不自动接着迭代，不把本流程理解为无限生成或自动采用。生图失败/超时先核查原调用，不重复提交。

- 先用已授权的代表性候选验证绘画语言，再扩展依赖其画风和身份的资产。已有采用基准不无故重做。
- 对照参考检查线稿、阴影边缘、分层上色、局部渐变、环境色、头发高光和皮肤过渡。身份/构图正确与画风匹配分别判断；“更精细”“更干净”或仅加滤镜不能代替画风匹配。不编造无量化依据的相似度百分比。
- 干净度只控制无意噪点、脏污和伪影，不抹除必要混色、渐变、结构阴影或材质差异；不以全图模糊获得柔和，也不以硬边纯平涂获得干净。
- 反推描述正确不等于生成结果已通过。仍按[生图质量规则](../../../rules/image-generation-quality.md)派发用完即焚的独立审图子代理实际看图（主代理严禁看图），按影响判定与局部/整张重绘条件补救，每张最多一次；第一棒零占位符一步到位写死完整画风母词与人物造型并由 `verify-script-alignment` 拦截残余占位符（`fill-style` 仅作跨集画风二次统一刷新备用），Stage A 经 `prep-prototype-refs`（`prep-historical-refs`）与免冠露额 `prototype-sheet`（`historical-sheet`）过审解锁后再放行下游，接触表（`contact` / `review-grid`）与 `finalize` 强制要求每单元 `>= 12` 字独立具体审图理由（禁套话雷同触发 `FINALIZE_BLOCKED_FAKE_BULK_PASS`），双检通过后自动归位推进，仅将一次补救后仍未通过或无法确定的图片汇总交用户审核；用户改变方向时，已提交的旧方向结果单独保存，不伪称按最新prompt生成。

## 案例边界：日系商业动画参考

当实际参考呈现此画法时，可反推为：细而清晰的深灰线稿，外轮廓略重、内部线较细；赛璐璐底色配两至三层清晰明暗，**硬边分层阴影为主，局部柔和渐变为辅**；以渐变补充皮肤、发束和材质体积，保持二维感。冷色环境光按场景进入暗部，头发用断续冷色窄带高光，避免大块U形硬高光。弱笔触，低至中饱和，肤色明亮。

此案例不能推广为所有动画风格。不能因参考有柔光叠加就改成全幅软边渐变或三维插画，也不能删除全部渐变退回纯平涂。具体角色脸型、黑长发、制服、沙发、酒红点缀均不是通用必要项，须服从内容源图和当前项目。
